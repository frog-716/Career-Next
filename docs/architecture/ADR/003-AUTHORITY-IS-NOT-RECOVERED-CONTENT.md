# ADR-003｜执行权限不等于恢复内容

**状态：V2 修订，等待最终架构审查。**  
**日期：2026-10-02**  
**依据：AI-01、07、10～17、MG-03～05。**

## 决定

模型执行器不拥有事实写权限，也不拥有授予权限的能力。许可由可信用户路径授予并由独立控制器检查；AI 来源经 UI/子任务/摘要转换后不能洗成人工授权。读、外发、目标变更与接收方分别约束。

任务与 Proposal 内容可以持久化/恢复，执行 capability 和秘密存储不随业务备份恢复。普通 backend restart 保留 workspaceInstance、更换 backendGeneration；restore/workspace switch 更换资料实例，MessagePort 重连只更换 connectionGeneration。旧任务/预算元数据不能重新成为执行许可，新连接不自动重放命令。用户接受内容时仍通过当前依赖校验与目标 owner 的本地原子事务。

V2 的权限 provenance 由 Runtime 按真实交付输入计算，模型 citation 不可缩小。所有生产者持久化前检查来源/目标清除代次，清除覆盖受管理副本且可靠阻断迟到写回；恢复 pending Proposal 后，当前用户仍可按当前权限进行新的本地接受。

协议正文仅在 [AI-RUNTIME](../AI-RUNTIME.md#actors) 和 [DATA 的恢复/Secret 边界](../DATA.md#backup) 维护。

## 为什么值得记录

若最初将“模型能调用某工具”当成“用户已授权”，或把可执行许可与资料同包备份，未来换强模型、增加工具、恢复旧库时都会放大权限漏洞。之后补救会涉及所有调用入口、历史任务和用户信任边界，而非替换一个 SDK。

## 接受的代价

必须区分 Actor、任务、单次外发、Proposal、正式内容和本地回执；不能用一个 status 字段概括。未知外发结果可能永久未知，恢复后重新外发需要新授权，不能以无感续跑为理由隐式重复计费。

## 放弃的替代

永久全库任务许可、可重放的备份 token、模型自行接受 Proposal、UI 自动化伪装人工、Provider 自动 fallback，以及把重跑称为恢复，都不满足冻结权限模型。

## 重新讨论的触发条件

新增真正需要操作用户桌面/外部写系统的正式产品需求，必须先建立独立可信的人类确认边界。更强模型、更长 Context 或更多子任务不是降低这些边界的理由。
