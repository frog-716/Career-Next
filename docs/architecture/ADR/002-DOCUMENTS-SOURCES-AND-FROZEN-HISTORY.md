# ADR-002｜自有文档格式、来源身份与冻结历史

**状态：V2 修订，等待最终架构审查。**  
**日期：2026-10-02**  
**依据：DM-01、07、11～15、21～25、31、38，UX-06～08。**

## 决定

Resume 正文采用 Career 自有、版本化、受限的结构化文档；编辑器和打印引擎是适配器，不以某个库的全部内部状态或截图当唯一数据格式。当前身份由 Profile 组合；历史文稿和现实发送/接受材料冻结当时值，保留各自独立业务身份与文件保留理由。

来源引用绑定实际 owner、对象、版本与定位。文件 hash 只承担字节完整性/物理去重，不承担现实事件、人物或 Raw 的身份判定。旧版本不可读就明确不可读，不以当前正文替代。

V2 将导出起点固定绑定 Resume revision 与 Profile revision；文件发布先建 hold，再发布不可变 blob，在正式事务交接 retention，GC 删除认领与保留互斥。Raw 生命周期仍服从具体 Domain 语义，不统一开放普通编辑。

格式与文件发布正文见 [DATA §4～5](../DATA.md#resume-data)，来源边界见 [MODULES §4](../MODULES.md#source-boundary)，不在 ADR 重复详细规则。

## 为什么值得记录

文档、来源和历史会随多年使用积累，错误的数据格式/身份关系会使后续换编辑器、纠正来源和清除敏感内容必须批量重写用户资料。冻结历史不应依赖未来引擎仍能生成相似 PDF。

## 接受的代价

需要维护 Career 文档与 Tiptap 的往返适配、明确支持的格式集合、格式迁移和旧文档只读兼容。不可变导出物占用存储；必须有明确清除与引用保留管理，而不是无限自动缓存。

## 放弃的替代

全量 HTML、截图、任意编辑器内部 JSON、所有当前文稿内复制 Profile、只保存“目前最新版本”的指针，都会把长期资料语义绑定到易变呈现，或无法区分当时与现在。

## 重新讨论的触发条件

新的正式编辑能力无法被现有格式无损表达，或已执行的格式往返/迁移验收发现缺陷。变更需要版本化迁移和真实历史回读验证，不能由视觉优化顺手覆盖旧格式。
