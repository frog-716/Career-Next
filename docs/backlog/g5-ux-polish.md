# G5 后续 UI / UX polish

来源：2026-10-03 独立 Computer Use 与用户最终真人验收。三项均为体验 backlog，不阻断已通过的本轮真人 Desktop，不改变 Frozen 产品规则；本轮仅记录，不实施。

| 发现 | 后续改进目标 | 保留的边界 |
| --- | --- | --- |
| AI / Proposal 显示大量 ID、JSON、工程状态，普通用户难以理解 | 首屏用可理解的对象名、建议正文与操作结果说明；技术细节按需展开 | 最终请求预览仍须准确说明读取/外发内容与接收方，不隐藏重要授权信息 |
| outcome_unknown 的核对/继续原命令按钮缺少直白下一步 | 说明“现在是否已保存”“先核对什么”“核对结果后点哪个按钮”，区分查询回执与新外部请求 | 保留同一命令身份，不自动重复外发，不把未知结果当成功 |
| 左侧纯图标导航首次使用辨识度弱 | 让首次使用者能看出导航入口与四个主要页面名称 | 四入口与业务 owner 不变，不新增产品语义正本 |

原始困惑见 [Computer Use](../verification/g5-computer-use-manual.md)，最终真人证据见 [人工结算](../verification/g5-manual-desktop-final.md)。后续实施需独立授权，不进入 G6。
