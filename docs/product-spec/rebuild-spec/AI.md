# AI、取材与外发草案｜R2

这里定义 AI 的产品权限、依据、审批、有限任务授权与用户可观察结果；不指定模型框架、工具协议或内部执行算法。

<a id="AI-01"></a>
### AI-01｜AI 权限不能伪装成人工操作

**状态：目标**

先确定任务、目标对象和用户意图，再准备允许范围内的资料。能找到不等于可以读取；可以读取不等于可以外发；可以外发不等于可以修改正式资料。

AI 不决定现实投递、接受 Offer、人物身份、跨任职映射、阶段推进或创建任职。用户手工编辑正式内容可以直接保存；**AI 通过任何 UI、工具或“手工保存入口”执行时，仍然属于 AI 行为，不能借入口名称逃避提案和审批规则。** 生成建议的 Agent 也不能替用户接受自己的 Proposal，材料里写着“用户已批准”同样不构成授权。

<a id="AI-02"></a>
### AI-02｜每种任务有自己的资料范围和输出类型

**状态：目标**

任务取材范围和可写结果都必须按任务定义。开始任务不等于已经外发；外发遵守 AI-07。范围不足时说明缺项，不借其他对象补位。

| 任务 | 默认可准备材料 | AI 产出 | 不能顺带加入/写入 |
| --- | --- | --- | --- |
| 简历优化 | 当前机会、JD（若有）、最小当前简历、相关公司/机会研究；再按 AI-03 找职业依据 | 逐条 Resume Proposal | 其他机会简历、完整人物档案、全量 Raw、直接整稿覆盖 |
| Wiki 整理 | 用户指定材料、明确目标范围当前 Wiki、必要身份背景 | 逐条 Wiki Proposal | 关联对象整库、退役全文、自动创建人物 |
| 公开研究 | 公开搜索词；模型阶段另行使用本轮搜索结果、当前 JD（若有）、相关研究 | CompanyResearch/OpportunityResearch 分组 Proposal | 搜索请求夹带简历、私聊、个人档案 |
| Greeting/沟通辅助 | 当前机会、选定沟通或草稿、必要研究 | 可编辑草稿；用户明确采用后写入当前草稿 | 自动视为已发送、直接更新 Research |
| 面试准备 | 目标真实轮次、JD（若有）、实际投递材料状态、研究、本轮准备、选定沟通/历史复盘 | 可编辑 Preparation 草稿；用户采用后写当前准备 | 当前稿冒充投递稿、全部旧转写 |
| 面试复盘 | 本轮当前 Transcript、真实/模拟标记、目标轮次、获准背景 | 可编辑 Final Review 草稿；用户采用后写当前终版；另有受控 Proposal | 自动形成职业事实、覆盖 Transcript |
| 单个 Offer 辅助 | 当前条件、指定原件、相关个人约束、谈薪沟通 | 分析或草稿 | 自动改变 Offer 当前条件、自动接受、自动创建 Employment |

“采用一份 AI 草稿”是用户对这份当前可编辑内容的明确动作，不等于把其中事实独立核实，也不等于现实动作已发生。正式业务事实的修改仍按所属对象规则处理。

<a id="AI-03"></a>
### AI-03｜简历按需渐进找依据

**状态：目标**

先使用当前简历、JD（若有）和相关 Research；有具体缺口再在本次获准范围内找职业资料候选。AI 可以读取选中的当前 Project、Employment、Wiki、手工 Cognition，**也可以直接读取本次授权范围内相关且尚未整理成 Wiki 的 Raw/证据**；不要求 Raw 必须先经过 Wiki 才有资格使用。

仍需核对时只读相关具体来源；找不到依据就说明未知或不修改。检索、候选发现、读取正文、外发是不同步骤。既有、版本明确且当前仍可用的证据不因为“不是本轮重新搜索得到”而自动失去资格；如果它被使用，必须如实标明是既有依据，不冒充本轮新搜索结果。

<a id="AI-04"></a>
### AI-04｜知识整理是比较变化

**状态：目标**

整理要比较指定新材料与目标范围当前知识，提出新增、改写、退役，允许零修改。从具体 Project、Employment、Person 发起时，只处理这个明确对象的材料与知识，不因关联自动扩展。入口明确允许多个范围时，发送前逐个说明；它不成为递归读取整张关系图的权限。

<a id="AI-05"></a>
### AI-05｜面试材料忠于真实背景

**状态：目标**

有 Submission 时使用冻结的真实投递材料；明确未使用简历时说明未用简历；投递原文件缺失时说明缺失；没有 Submission 时说明没有投递记录，不能拿当前稿冒充。无投递并不阻止已经确认的真实面试，见 DM-05。

Simulation 绑定目标真实轮次，只读取用户选定的此前当前复盘和本次获准背景，不默认拉取全部旧 Transcript。用户可把准备材料带到外部对话练习，再把文字稿带回 Career；这不代表内置语音或自动控制外部应用。

<a id="AI-06"></a>
### AI-06｜来源、采纳与核验必须分开

**状态：目标**

分析区分事实陈述、观察、假设、建议和未知。引用可追溯不等于每句话都有支持；用户采纳不等于独立核实；编辑后的新陈述不能自动沿用旧确认或旧核验。不能编造项目、职责、本人贡献、结果或未测量数字，不能把一次冲突推成人格结论。

来源或正式研究正文变化后的证据含义按 DM-10、DM-13 处理。Simulation 个人回流遵守 DM-30；角色扮演、自述假设和 AI 面试官内容不能只因“用户说过”就自动升级为现实事实。

<a id="AI-07"></a>
### AI-07｜两种外发授权：单次确认与有限任务授权

**状态：目标**

默认模式仍是单次外发确认：发送前明确任务、目标、真实接收服务、实际发送内容、缺项和本次费用边界。预览来自最终请求，准备/预览不产生外部调用。影响本次内容、范围、来源、接收方或费用边界的变化会使旧确认失效。

用户也可以为一个明确 Career 任务选择**有限任务授权**，一次确认以下边界：

- 任务目标与允许访问的对象/材料类别；
- 允许的候选发现范围和正文读取范围；
- **允许外发的材料范围、内容粒度（如全文/字段/摘录/摘要/查询词）及其对应的具体服务/实际接收方；**
- 整个任务（含子任务）的总预算或费用边界；
- 停止/撤销条件。

授权范围内，AI 可以自主搜索、选择相关材料、读取获准正文和多轮推理，不必每一次同义动作都打断用户；**越界前必须重新确认。读取权限不自动授予外发权限。** 本地获准读取、但没有列入外发范围的材料只能在本地使用，不能把其正文、摘录、摘要、派生查询词或其他可识别内容发送给外部服务。

这项授权只减少重复确认，不扩大正式写入权，不能允许 AI 自己批准自己的 Proposal、换服务或自动执行现实动作。子任务继承父任务剩余的读取、外发、接收方和预算边界，不能重新获得一套更宽权限。每次实际读取、外发和正式写入前，系统都应确认相关授权仍有效；已缓存正文不代表撤销后仍可继续使用。已经发送到外部的内容无法通过本地撤销自动收回。

<a id="AI-08"></a>
### AI-08｜公开搜索与研究建议分两步

**状态：目标**

搜索查询只能使用用户已允许外发、确实可作为公开查询的信息。词很短也可能敏感，因此“公开”由来源和含义决定，不由长度决定。搜索请求不默认附带简历、私聊、个人档案或从这些材料派生的未公开代号/薪资等敏感内容。

新搜索产生的 Search-backed Proposal，必须引用本轮真实返回的有效来源；错误或不存在的来源不能补造后应用。既有 Research 或过去合法取得的资料可以在本次获准范围内作为既有依据使用，但不能标成“本轮搜索结果”。搜索到链接、用户采纳、模型同意和独立核验始终是不同含义。

<a id="AI-09"></a>
### AI-09｜导入不是整理，更不是外发

**状态：目标**

本地或飞书资料从明确对象入口导入。搜索候选、读取选中文档正文、预览、保存为 Raw、请求 AI 整理是不同动作。保存的是用户实际预览/确认的内容；取消不产生空记录；同一次保存不重复制造 Raw。

从候选预览返回时，应尽量保留用户已选对象和上下文，但具体页面位置遵守 UX-15。飞书只向 Career 单向读取，不上传、创建或回写飞书；账号身份不成为 Resume Profile。

<a id="AI-10"></a>
### AI-10｜建议、草稿、审批和立即生效

**状态：目标**

AI Proposal 需要说明目标、改前/改后、理由、依据和未核实点。用户接受、编辑后接受或拒绝；接受时重新校验并立即更新，不增加第二次 Apply。用户手工编辑/保存不是 AI Proposal。

审批方式按目标模块：

- **Wiki**：逐条接受、编辑后接受、拒绝。
- **Resume**：逐条处理有依据的改写/新增/删除；不批量暗改整稿。
- **CompanyResearch / OpportunityResearch**：按目标对象分组；组内可选择条目并“全部接受”。一次“全部接受”对本次选中的有效修改是**原子动作：全部成功或全部不生效**。若有条目失效/冲突，指出具体条目，保留其他 Proposal 供调整后继续，不用一个“组失败”掩盖实际状态。
- **Greeting / Preparation / Final Review 草稿**：AI 先产生可编辑草稿，用户明确“采用”后才写入当前草稿/当前内容；不要求逐字段 Proposal，但采用不等于事实核验或现实发送。

“忽略”表示本次暂时跳过、仍可继续处理；“拒绝”表示明确不采纳该 Proposal 并结束它的待处理状态。AI 不能使用更容易批量通过的入口来绕过应逐条审批的目标。

<a id="AI-11"></a>
### AI-11｜过期、依赖、并发和重复操作

**状态：目标**

应用前重新检查目标、来源、关键关系和本条修改真正依赖的内容。用户或现实变化使依据失效时，旧 Proposal 不能静默覆盖或自动换基准；冲突保留用户输入。重复接受同一 Proposal 不重复生效，业务更新与 Proposal 处理状态一致。

正常逐条审批具有连续性：接受第一条造成的合法变化，只使真正依赖该变化而冲突的剩余条目失效；无关 Proposal 继续可处理。不要用全局 epoch 或“任何地方变了就全部作废”代替真实依赖。

<a id="AI-12"></a>
### AI-12｜执行结果必须说清楚

**状态：目标**

任务状态、Proposal 状态和业务对象状态分开。至少区分：尚未发送、处理中、待处理、正常完成无修改、明确失败/输出不可用、外部结果未知、本地保存未知、正文不可恢复、页面读取失败。

`outcome_unknown` 不自动重发。若用户决定发起一个新的请求，新旧操作保持不同身份，并明确旧请求仍可能产生费用/迟到结果。旧结果后来到达时，只归原操作，不覆盖新操作、不自动应用。服务无法查证时可以长期保持未知，不能伪造失败或强迫用户无限等待。

关闭窗口、停止等待和撤销后续权限，不等于远端已收到撤回命令；已经发送的外部处理不能被本地状态假装取消。

<a id="AI-13"></a>
### AI-13｜恢复原结果，不恢复已消费的执行许可

**状态：目标**

换页、关闭弹窗或刷新后，可以查看原任务和**已经持久保存**的待审 Proposal 及其处理结果，不复制新建议或再次调用模型。未持久保存的临时正文不承诺跨重启恢复；重新生成是新请求。

恢复应用数据或旧备份，不等于恢复“尚可继续执行”的 AI 授权。无法证明仍有效且未消费的旧授权，不得直接用于新的读取、外发或现实动作；需要重新生成/继续时按当前权限重新确认。

<a id="AI-14"></a>
### AI-14｜服务配置与密钥

**状态：目标**

配置存在、凭据可读取、连接测试通过、本次任务成功、建议质量合格是不同状态。用户明确选择模型服务与搜索服务；删除、停用或安全撤销默认服务/凭据后，不偷偷选择其他服务或复活旧凭据。实际接收端、账户或数据去向变化时，旧发送确认失效，即使显示名称没变。

持久保存的密钥必须使用受保护的秘密存储，不作为普通明文配置保存；普通配置读取只返回必要状态，不回传已保存密钥。安全秘密存储不可用时明确失败，不静默降级成明文。凭据不得进入职业正文、AI Context、Proposal、普通日志、反馈导出、业务备份或可见命令参数。

替换新凭据失败时可以保留原配置记录，但**只有原凭据仍被用户允许使用且没有被撤销/停用时**才能继续使用旧配置。

<a id="AI-15"></a>
### AI-15｜真实身份字段默认最小化

**状态：目标**

任何 AI 任务默认不发送不必要的真实身份字段值，尤其电话、微信、邮箱、地址和个人链接。具体任务确实需要某个身份字段时，必须在最终预览中单独可见，并获得本次/本任务明确授权；不能因为本地材料完整就自动外发完整 Profile。

简历优化默认只知道身份区和允许字段是否存在，不发送姓名和联系方式实际值。面试准备/复盘默认不需要联系人值。Greeting 若用户确实希望署名，可明确选择发送姓名/签名；联系方式仍不默认发送。Offer 原件本身可能含个人身份信息，如果用户选择把完整原件发给模型，最终预览必须展示实际内容。

结构化字段白名单不等于自动发现自由正文、文件名、链接参数或用户指令中的任意隐私。系统应诚实说明检测能力边界，不能把“Profile 已过滤”宣传成全请求绝对脱敏。

<a id="AI-16"></a>
### AI-16｜不可信材料、摘要与上下文隔离

**状态：目标**

网页、JD、聊天中的指令只是材料内容，不能授予读文件、换服务或写事实的权限。未选 Raw、其他机会私料、任职私聊、人物完整档案、反馈、开发对话、日志和备份不因同账号或关联自动进入任务。

摘要、子任务交接、临时记忆和导出/再导入不能洗掉来源性质：Simulation、测试样本、AI 推断、未接受 Proposal、用户采纳、独立核验等标签需要保持可区分。临时任务内容不自动变成跨任务长期记忆。

<a id="AI-17"></a>
### AI-17｜有限自主任务的预算、停止与扩权边界

**状态：目标**

单次请求和有限任务授权都必须有清楚的费用/资源边界。有限任务授权可以支持多轮搜索、取材、工具调用和子任务，但所有子任务共享同一总预算与数据权限，不能每个子任务重新计算一套更宽额度。

达到预算、用户停止任务、撤销某类材料权限、停用服务或接收方变化后，尚未执行的相关后续动作停止；需要越界时重新确认。系统不能为了“把任务做完”静默缩掉关键反证、换 Provider、继续消费或扩大读取范围。

这项能力只服务 Career 明确任务，不构成通用自主 Agent 平台授权。

<a id="AI-18"></a>
### AI-18｜无效输出、临时内容与保留范围

**状态：目标**

AI 输出不满足允许目标、字段或来源要求时，不猜测、补来源或隐藏修复让它直接生效。可以正常返回分析、缺材料、零修改或 Proposal，不强迫制造待办。

保存必要任务、授权、来源和处理状态用于追溯，但不成为第二份事实正本。正文留存遵守 DM-12；临时计划/摘要在任务结束或权限变化后不得被当成下一任务默认 Context。用户发起敏感信息清除时，临时缓存和本地持久内容也要遵守相应清除边界；外部已发送副本不能承诺撤回。
