# 用户体验草案｜R2

保留能完成任务的编辑、保存、导航、纠错和恢复体验，不照搬旧页面布局。视觉方向只引用 PR-06。

<a id="UX-01"></a>
### UX-01｜第一次打开与空状态

**状态：目标**

打开本地应用后可以直接进入工作区并开始记录。Opportunity 创建最低只要求公司＋岗位名称，JD 可后补；缺 JD 只限制依赖 JD 的分析，不阻止记录真实联系。

Opportunity、Project、Employment 的空状态都有可用创建入口，与列表新增使用同一流程；只打开表单再取消不产生记录。Wiki 为空时既可以从明确业务对象写知识，也可以进入 Personal/Cognition 明确范围手工写第一条个人知识；不因此建立“万能资料 Inbox”。

<a id="UX-02"></a>
### UX-02｜置顶模块就是默认首页偏好

**状态：目标**

四个业务模块可排序；用户最多选择一个置顶模块。置顶项排第一，并成为没有明确对象目标时的启动首页。没有置顶时使用稳定默认顺序，Wiki 在第一位。不存在另一份独立“默认首页”设置与置顶规则争夺控制权。

明确链接永远优先；无效偏好安全回落到四模块。收起侧栏只改变空间，不重建正在编辑的表单、选区或当前对象。

本稿没有新增“具体业务对象置顶”需求。

<a id="UX-03"></a>
### UX-03｜工作区围绕当前对象，返回动作说清目的

**状态：目标**

机会显示公司、岗位、阶段、结果、阶段日期、当前任务、岗位情报、发送材料和活动；Project、Employment、Person 展示同一个对象的当前理解、支持材料与相关入口，不各存一份总结。Resume Editor 持续显示所属 Opportunity；切换 Resume 后，“返回所属机会”跟随当前 Resume 的 owner。

必须区分：**返回所属对象、返回列表、返回来处、浏览器后退**。只有“返回所属对象”由对象 owner 唯一决定；其他返回行为遵守 UX-15 的会话保持规则，不能一律重定向到所属对象。

指定对象打不开应报错并给出安全返回路径，不自动打开另一个同类对象。机会整行可点击并支持键盘进入。日常 UI 不要求用户编辑内部 ID、revision、hash、请求 JSON。

<a id="UX-04"></a>
### UX-04｜保存状态、冲突与迟到响应

**状态：目标**

明确区分未保存、保存中、已保存、冲突和结果待核对。保存成功但回读失败时说明“已保存、暂时未刷新”，提供重新读取动作，不诱导重复保存。读取持续失败时保留当前工作和已知保存结果，不能永久卡死在一个模糊错误提示。

并发冲突时保留本地输入，展示可理解的差异/当前服务器版本，并给用户重新保存或放弃本地改动的路径；不能静默覆盖。切换到 B 后，A 的迟到读取或保存结果不能覆盖 B，也不能显示成 B 的保存成功；A 的结果仍可在 A 或相关状态入口查看。

<a id="UX-05"></a>
### UX-05｜离开编辑与“取消”语义

**状态：目标**

有尚未保存的输入时，关闭弹窗、按 Escape、切页、主动刷新、切 Resume、恢复旧版等主动离开动作要保留输入或让用户明确决定是否丢弃。空表单没有输入时，取消无需额外确认。

当前内容已自动保存时，关闭/取消只是离开，不得暗示已保存改动会撤销。恢复旧版会改变当前稿，需要确认；取消恢复后回到版本查看流程。AI 尚未发送、已经发送、用户停止等待分别按 AI-07/AI-12 表达，不能都用一个“取消”词假装远端已撤回。

意外崩溃后的未提交字符保证见 UX-15，不由本条虚构。

<a id="UX-06"></a>
### UX-06｜Resume Editor 是连续可编辑的纸面

**状态：目标**

保留 A4 纸面直接编辑、结构化技能/经历/项目/教育、条目与要点增删调整、格式、撤销重做、选区保持、当前 Resume 内查找替换和溢出检查。点击格式工具仍作用于原选中文字。

自动保存不能频繁打断中文输入、选区和撤销。当前 ResumeDocument 的手工正文/格式编辑，以及用户**接受一条 AI Resume Proposal 后产生的内容修改**，都作为当前编辑会话中的可撤销编辑；每次接受 AI 修改按一次清楚的编辑事务进入撤销链。撤销该内容修改只表示用户随后把当前稿改回，不把原 Proposal 重新变成待审，也不抹掉它曾被接受的历史。

打开版本历史、查看版本或取消恢复都不修改当前稿，也不清空当前编辑会话的撤销链。用户确认“恢复某版本”时，只把该版本内容写入当前稿，源版本保持冻结；该恢复在当前编辑会话中作为一次可撤销替换。刷新/重启后不承诺恢复撤销链，仍以已持久保存的当前稿和版本历史为准。

Profile 同步是全局 Profile 的正式修改，不进入某一份 ResumeDocument 的局部撤销链；需要改回身份值时再次修改 Profile，并按 DM-01 同步所有当前 Resume，不能通过单份简历撤销制造第二份当前身份正本。依赖已保存内容的 AI、命名版本和导出动作，在需要稳定快照时先完成当前稿保存；冲突时不继续拿旧内容执行。

在当前纸面身份区修改受管理的姓名/联系方式，明确表示修改全局 Profile，并按 DM-01 同步其他当前 Resume；UI 要告诉用户这不是只改这一份简历。

<a id="UX-07"></a>
### UX-07｜快捷键、中文输入与焦点属于正式体验

**状态：目标**

⌘S 打开命名版本保存，不保存网页；⌘F 在当前 Resume 中查找替换。复制、剪切、粘贴、加粗、撤销重做有效；⌘A 的作用域符合当前编辑区域。⌘⇧←/→ 在真实 macOS 编辑体验中验证最终选区，不只验证按键监听。

中文输入法候选尚未提交时，自动保存、快捷键和格式操作不能破坏输入。打开命名弹窗、取消后应回到合理焦点/选区；重复按 ⌘S 不制造多个并行命名流程。核心弹窗支持键盘操作并正确返回焦点。

<a id="UX-08"></a>
### UX-08｜PDF 与实际发送材料可追溯

**状态：目标**

导出不是截图，也不依赖用户调整浏览器打印设置。PDF 文字可选择复制，合法网页链接可点击，内容不静默截断；生成失败说明原因，不显示完成。

每次 Career 导出的 PDF 对应明确的源 Resume/版本与当时内容快照，之后继续编辑当前稿不会把旧导出物变成新内容。用户现实发送后登记 Submission 时，可以选择当时导出的文件/快照，或明确上传实际发送文件；原文件已经丢失时按 DM-23 诚实登记缺失，不能拿当前稿或新 PDF 冒充。

切换对象后才返回的 PDF 生成结果必须保留原 owner，不自动显示成当前对象的导出成功。

<a id="UX-09"></a>
### UX-09｜Wiki 先读内容，再看性质、来源和历史

**状态：目标**

首页默认最近更新的有效知识，提供 Project、Employment、Person、Cognition 的轻量阅读入口；Profile 为次级入口。知识详情突出对象、正文和可读来源；性质统一显示为 **事实陈述、观察、待验证判断**，不使用“已确认事实”替代 DM-14 的语义。

来源、用户采纳和独立核验需要时分别展示。无标签不占位；来源按需展开，历史能区分当前、旧版本和不再有效。OpportunityResearch 的内容可以从 Opportunity/Wiki 阅读入口引用，但不复制成第二份可修改正文。来源缺失/已清除时说明原因，不偷偷跳到最新版本。

<a id="UX-10"></a>
### UX-10｜AI 流程可理解、可停止、可接续

**状态：目标**

任务旁说明本次使用什么、为何使用、会改哪里；真实接收服务、授权范围、预算/停止条件在发送详情可见。单次确认与有限任务授权使用同一套清楚边界，不让用户编辑内部请求结构。

用户可以离开页面后从 AI 进度或所属对象找回原任务；“停止后续动作”只停止尚未执行的本地/Agent 行为，不声称已撤回远端请求。长期 `outcome_unknown`、用户主动发起新请求、旧结果迟到都按 AI-12 分开显示。

<a id="UX-11"></a>
### UX-11｜反馈不打断工作

**状态：目标**

反馈随时可达，可只写一句话，可选截图；保存后关闭并回到原任务。只自动记录必要的位置和版本信息，准确指向当前对象；不自动抓取页面正文、简历、聊天或截图。

反馈弹层与底下业务表单分别保护各自输入；保存结果未知时先核对同一反馈，不重复创建。保存成功后焦点回到合理位置。可以查看、补充、导出；永久清除及附件处置遵守 DM-38。反馈永不自动进入职业知识或求职 AI。

<a id="UX-12"></a>
### UX-12｜普通用户可完成备份与恢复

**状态：目标**

设置中让用户知道资料位置、最近恢复点、自动备份是否启用、备份是否完整，以及怎样手动备份、恢复、导出。用户可以启用/停用周期性自动备份；周期和保留数量可由后续架构/设置设计确定，不固定旧“周一 00:00”。

普通恢复与正式旧系统迁移分开。恢复前说明选中的副本、时间、完整性和影响；在独立位置核验并允许安全回退。缺文件/多余文件/不完整状态不能只显示“成功”。恢复完成后明确实际打开的是哪份资料以及仍缺什么。

<a id="UX-13"></a>
### UX-13｜本地启动、访问隔离与停止

**状态：目标**

只有能确认属于 Career 的实例才能复用或停止，不能仅凭端口占用误用、误停无关进程。启动失败给出可理解原因与安全重试路径；重复启动回到正确资料实例。真正就绪后再打开工作区。

Career 本地接口不能因应用开启就向无关网页、局域网或互联网请求开放，具体访问保护依 PR-01。关闭浏览器页面与停止服务分开。有进行中的保存/导出/迁移时停止要明确结果；停止失败不能显示“已退出”。睡眠或异常退出后重新启动时，只承诺恢复已保存内容和可持久恢复的任务状态。

<a id="UX-14"></a>
### UX-14｜桌面基础可用性必须实际验收

**状态：目标**

中文输入法、键盘进入与操作、弹窗焦点与焦点返回、缩放、长内容、窄窗口都属于正常桌面使用能力。主要动作和正文在合理缩放/窄窗口下仍可访问；不因缩小窗口把关键按钮挤没或要求用户理解内部滚动结构。

这些能力必须用真实交互验收，不能用“页面上有按钮”或源码字符串替代。R2 不因此新增移动端产品要求。

<a id="UX-15"></a>
### UX-15｜返回、换页、刷新和重启的保持矩阵

**状态：目标**

不同动作承诺不同，不用一句“全部恢复”模糊处理：

| 动作 | 至少保证 |
| --- | --- |
| 同一会话返回列表/来处 | 已保存对象、当前筛选/查询和有意义的位置尽量保留；无法精确恢复位置时不改变对象或筛选 |
| 切换对象再回来 | 各对象已保存正文、归属和独立编辑上下文不串；未保存输入按 UX-05 处理 |
| 主动刷新 | 已保存正文和对象可回读；未保存输入在刷新前须保护/确认，不承诺刷新后保留未写入字符 |
| 应用/浏览器重启 | 已持久保存正文、版本、Proposal/任务状态按其留存规则恢复；不默认恢复光标、选区、滚动、撤销栈 |
| 崩溃/断电 | 只能承诺最近成功保存/持久化的内容；启动后如实说明可能丢失的未提交编辑 |

这里的 **当前 Resume 编辑会话** 指：用户连续编辑同一个 ResumeDocument，期间没有切换到另一份 Resume、主动刷新、关闭/重启应用或发生等价的完整重新载入。仅打开/关闭该 Resume 的版本历史、查看版本、取消恢复或打开非破坏性的辅助面板，不结束这个编辑会话。

当前会话内选区/撤销栈按 UX-06 连续；切换到另一份 Resume、主动刷新或应用/浏览器重启会结束该 Resume 的本次编辑会话，之后只保证已持久保存的内容和历史，不承诺恢复旧选区或撤销栈。

<a id="UX-16"></a>
### UX-16｜业务日期与时区的输入和显示

**状态：目标**

用户界面必须按 DM-40 区分确认日、预约日/时刻、完成日、投递日、接受日、实际结束日和录入时间。日期可以单独存在；精确时刻按需填写；未知就是未知，不填午夜或今天占位。

有时区的精确时刻显示时可以按用户当前时区转换，但保留原事件时区/偏移的可追溯含义。历史补录显示实际发生日期与录入时间的区别。Opportunity 列表使用实际阶段进入日期，不拿下一步提醒日期无声替代。
