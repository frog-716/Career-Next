# Career 产品规格草案｜R2

本文件只定义产品目的、边界与范围。领域、AI、UX 和迁移细节由对应 Requirement ID 负责。

<a id="PR-01"></a>
### PR-01｜产品目的与本地访问边界

**状态：目标**

Career 是保存在个人电脑上的长期职业工作台。帮助用户推进求职、记录真实工作、形成以后还能找回和复用的职业积累。求职只是其中一段；在职求职、多个项目和重叠任职都可以并存，不要求每天填写所有模块。

Local-first 只说明主要资料在本机，不等于向局域网、互联网或任意网页开放。本地服务运行时，未经授权的外部网页或网络请求不能读取职业资料、修改业务对象或控制 Career。实现方式由后续架构决定，不要求复刻旧请求头、配对码或端口策略。

<a id="PR-02"></a>
### PR-02｜无 AI 也能完成手动闭环

**状态：目标**

首次使用不以配置模型、搜索服务或连接飞书为前提。用户能手动创建、查看、编辑职业资料，制作并导出简历，记录投递、沟通、面试和 Offer，保存复盘。外部能力缺失只影响依赖它的动作，不能展示假 AI 结果。应用本地可用不代表远端服务离线可用。

<a id="PR-03"></a>
### PR-03｜四个业务入口

**状态：目标**

一级业务入口只有 Wiki、机会、项目、任职。简历从所属机会进入；人物从任职、项目或相关知识进入；面试和 Offer 围绕机会。设置、反馈、AI 进度是辅助入口。

用户可将一个业务模块置顶；置顶模块排在第一位并成为没有具体目标链接时的首页。没有置顶时使用稳定的默认顺序，第一项为 Wiki。明确指向具体对象的链接永远优先于首页偏好。

<a id="PR-04"></a>
### PR-04｜事实、材料、认识和建议各归其位

**状态：目标**

原始材料保留原话与出处；业务对象拥有身份、关系和状态；Wiki、研究和复盘各保存职责内的当前认识；AI 提案只是尚待决定的修改；实际发送材料和接受 Offer 的依据属于历史事件。一个内容的正式保存位置，不等于它已被客观证实。对象关联不自动授予读取、外发或修改权限。

<a id="PR-05"></a>
### PR-05｜不继承的历史负担与本稿范围

**状态：目标**

不恢复自动跨经历提炼长期认知的新任务入口；保留手工长期认知及有价值历史。简历之间不共享当前稿，不要求维护复制谱系，不把成果资格、用途审批链设为相关材料复用的通行证。不自动建立全局人物名录、同名合并、人格或信任度评分；不设置接受建议后的第二次应用步骤。

本稿不要求云部署、多端同步、自动搜岗、全局智能收件箱、内置连续语音、多 Offer 比较或通用自主 Agent 平台。**有限任务授权**是 Career 具体任务内的受控能力，不等于建设通用 Agent 平台，详见 AI-07、AI-17。

功能退役、归档和永久清除是不同动作。退役功能不再提供新入口，不等于自动删除真实历史。

<a id="PR-06"></a>
### PR-06｜已登记的视觉方向

**状态：目标**

未来视觉工作参考 AIHOT 的克制设计语言和用户提供的 ChatGPT 窄侧栏方向；一级导航图标下方常显短名称标签。参考只影响视觉与交互表达，不增加业务对象或权限。本稿不选择组件库，也不把参考站点的具体业务或登录/订阅机制带进 Career。
