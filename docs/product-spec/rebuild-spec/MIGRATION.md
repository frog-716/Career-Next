# 数据保留、备份与迁移范围草案｜R2

这里定义需要保护的语义和用户可观察结果，不定义迁移程序或旧结构兼容实现。

<a id="MG-01"></a>
### MG-01｜先盘点，不推断真实资料

**状态：目标**

正式迁移前按记录和附件识别真实、明确测试、未知三类；“多数历史是测试”不能推广到全部数据。真实或未知资料不猜测删除，测试清理也要明确范围。本稿没有读取正式个人数据库，不提供真实迁移数量或清理授权。

<a id="MG-02"></a>
### MG-02｜迁移保留产品语义，不复制旧对象数量

**状态：目标**

需要保留：当前 Profile；Company/Opportunity 归属；Project/Employment/Person 及历史关系；Raw 与可读版本；Wiki 当前类型/历史/来源；Research 的内容、证据和撤回语义；独立 Resume 当前稿/普通版本；Submission 及实际材料状态（含文件缺失）；Communication；真实/模拟 Interview、Preparation、Transcript、Final Review；Offer 原件、当前条件和接受依据；手工 Cognition；有价值历史 Proposal；Feedback 及附件。

不要求复刻旧表、类、T14、ResumeUse、旧 Candidate 链或其他退役正本。无法映射的内容明确列为未映射，不偷偷丢弃或猜事实。

<a id="MG-03"></a>
### MG-03｜退役功能的数据与执行入口分开

**状态：目标**

退役功能不再提供新执行入口，不等于删除原资料或自动接受/拒绝历史 Proposal。区分：可转为现行资料、只读历史、仍待用户处理的建议。保留必要身份、状态和依据，但不为查看历史重建退役引擎。

<a id="MG-04"></a>
### MG-04｜备份、周期自动备份与恢复完整性

**状态：目标**

备份覆盖相互依赖的业务记录、Raw/原件、附件、Resume/PDF 和必要来源关系。能区分完整可恢复、缺文件的不完整、需要隔离核对的多余文件，以及只是核验旧快照；不能只恢复数据库后宣布全部成功。

用户可以明确启用/停用周期自动备份，也可以手动建立恢复点。具体周期、保留数量、调度器和目录由后续架构决定，不固定旧每周一或旧脚本算法。自动与手动备份遵守同一完整性和错误说明规则。

普通恢复先在安全/独立位置核验，避免覆盖唯一原件；恢复完成后说明实际恢复到哪份资料、缺什么、是否可以回退。永久清除某资料时，界面需要说明现有本地备份可能仍包含旧副本，并提供后续备份清理/自然过期的真实边界；不能声称能删除外部或用户已复制出去的副本。

<a id="MG-05"></a>
### MG-05｜凭据不随业务备份迁移

**状态：目标**

真实服务密钥由 AI-14 定义的受保护秘密存储管理，不进入业务备份、普通日志或资料导出。恢复业务资料不恢复已消费的 AI 授权，也不自动恢复外部服务访问资格；需要时重新配置/确认。迁移不要求复制历史凭据引用结构。

<a id="MG-06"></a>
### MG-06｜未知、缺失和历史错误不能洗成确定事实

**状态：目标**

历史未知日期、真实/模拟类型、人物身份、Greeting 是否使用、Submission 文件是否缺失，都继续保持未知/缺失含义。多条历史投递不静默合并成一次；无法满足新规则的内容可保留为待核对历史，不强迫生成假事件。

晚录、纠错与后来真实变化按 DM-39 区分；用户编写与 AI 生成后被用户采纳也不能只凭一个“user”标签混为一谈。

<a id="MG-07"></a>
### MG-07｜正式旧系统迁移与日常恢复分开

**状态：目标**

J-09 是新 Career 日常备份/恢复旅程；正式从旧 Career 迁入真实用户资料则必须取得实际数据清单，先备份、隔离演练、核对语义/数量/文件/引用及失败恢复，再在明确授权范围内处理正式资料。应用启动不暗中迁移数据。

旧测试通过、备份能打开、普通恢复成功，都不能单独证明正式旧数据迁移已经通过。
