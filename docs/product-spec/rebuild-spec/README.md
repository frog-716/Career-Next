## 已冻结的八组产品决定

1. **按真实情况记录，不强迫顺序。** 公司＋岗位即可建机会，JD 可后补；允许先沟通、直接约面、直接记录收到 Offer；日期可未知；补录历史不伪造前序事件。
2. **纠错与后来真实变化分开。** 误操作修正同一对象；真正后来变化记录为新的现实变化；项目可明确重开，未来离职日不提前把任职变历史。
3. **真实事件与材料完整度分开。** 确实发生的投递可在原文件缺失时如实登记；不能拿后来内容冒充当时内容；接受 Offer 绑定当时接受的条件。
4. **当前知识只有一个可修改正本。** 岗位、团队、招聘流程等机会信息归 OpportunityResearch；机会 Wiki 只引用/展示这些内容，不维护重复正文。
5. **支持有限任务授权。** 默认仍可逐次确认；用户也可给一个明确 Career 任务授权资料范围、服务、总预算和停止条件，让 AI 在范围内多轮工作，但不扩大正式写入权。
6. **模拟中的真实本人补充可受控回流。** 用户主动选择片段并确认真实含义后，可形成个人/项目知识的待审建议；模拟面试官虚构内容不能回流为现实事实。
7. **连续编辑的保障范围明确。** 同会话尽量保留筛选、位置和当前文稿上下文；刷新/重启只保证已保存内容；冲突有比较和继续保存路径；中文输入、焦点、快捷键属于正常可用性。
8. **归档与真正清除分开，并保留自动备份。** 整理列表用归档；误导入或敏感资料支持明确永久清除并展示影响；共享引用不静默连删；用户可启停周期自动备份并完成普通恢复。

## 已同步修正的非选择性问题

- Wiki `Fact` 统一显示为“事实陈述”，不再由 UI 偷偷升级为“已确认事实”。
- 用户手工保存正式资料直接生效；只有 AI 提出的修改走 AI 审批。
- OpportunityResearch 与机会 Wiki 的重叠 owner 已收敛。
- 本地保存不等于向局域网、互联网或无关网页开放；外部未授权请求不得读取、修改或控制 Career。
- 持久化密钥必须使用受保护的秘密存储；普通配置读取不得回传真实密钥；安全存储不可用时不静默降级明文。
- 日常备份/恢复旅程与正式旧系统迁移分开。

## 使用边界与下一步

`rebuild-spec/` 是与旧实现解耦的**冻结产品输入**。`audit/` 只用于追溯 R1→R3 的决定和证据，不要求未来开发 Agent 阅读旧仓。

R3 仍未选择最终技术栈、数据库表、API、框架、目录实现或桌面打包方式。没有运行任何产品测试，也没有验证正式用户数据、真实 AI、真实飞书或生产迁移。

**下一步进入全新架构设计。架构 Agent 以本 `rebuild-spec/` 为产品合同；旧 Career 只在出现无法解释的证据问题时由独立审计者回查，不作为设计模板。**
