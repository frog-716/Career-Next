# R2 冻结前定向对抗审查与 R3 收口

状态：**已完成。R3 产品规格冻结。**

来源：用户在 2026-10-02 提供的 R2 冻结前定向 Reviewer 输出。该 Reviewer 给出 `DO NOT FREEZE`，指出 2 项 P0、4 项 P1、1 项 P2 重复维护风险。主 Thread 复核后认为这些问题均可通过局部规格修正解决，不需要重新蒸馏旧 Career 或重开五轮全面审查。

## 冻结阻断的处理

1. `AI-07`：有限任务授权新增独立的**外发范围/内容粒度/接收方**，读取权限不再被解释为外发权限；正文、摘录、摘要和派生查询词均受外发边界约束。
2. `DM-31`：已接受条件若被新的有效条件明确替代、且用户尚未接受新条件，Opportunity 保持 Offer 阶段并回到 `active`；旧 accepted 及接受依据留在历史。新条件再次被接受时形成新的接受依据。
3. `DM-31`：口头 Offer、从未存在原件或历史原件丢失可以诚实记录已知条件、未知项与来源说明；本次保存原件失败不能伪装成历史缺失。
4. `UX-06 / UX-15`：定义 Resume 当前编辑会话与撤销边界。手工编辑和已接受 AI Resume 修改进入文稿撤销链；撤销内容不把 Proposal 重新变成待审；查看/取消历史不结束会话；Profile 是全局修改，不进入单份 Resume 的局部撤销链。
5. `AC-AI-15-01`：收窄为受管理身份字段默认最小化 + 明确授权例外，不承诺自由正文万能脱敏。
6. `AC-UX-09-01`：唯一正本不再被误写成唯一 UI 编辑入口；多个入口可以操作同一个 ResearchItem，但不能产生第二份可独立修改正文。

## 非阻断维护收口

- `DM-36` 唯一负责 Project 完成/取消后的真实重开，`DM-16` 只引用。
- `DM-34` 唯一负责 Employment 计划结束/实际结束与结束后修正，`DM-17` 只引用。
- `DM-37` 唯一负责 Interview 终态误操作纠错，`DM-28` 只引用。

## 冻结裁决

R2 Reviewer 的最小阻断集已经全部处理；未新增 Requirement ID，也未改变此前用户确认的八组产品方向。R3 共有 87 个 Requirement ID、104 个验收分支、9 条 Journey。
