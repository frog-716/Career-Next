## 3. 全局导航与首页

左侧始终只有 **Wiki / 机会 / 项目 / 任职** 四个业务项，每项“图标+常显短名称”，当前项清楚高亮。窄模式也不隐藏名称，不依赖hover才知道入口。设置、帮助、反馈是底部辅助入口，视觉上与四个业务模块分组；Profile从次级“我的基础资料”进入，人物从任职/项目/相关知识进入。

置顶和排序放入“调整导航”，不在每个业务项下面常驻两枚按钮。最多一个置顶模块；置顶即首页；无置顶仍先到Wiki。具体对象链接优先，不先跳首页或强制走教程。

**首页是当前默认模块的开始区域，不新增第五个模块或第二份首页偏好。**

新用户首次显示完整欢迎区；已使用者可收起为“开始使用”入口。继续看已有资料优先，教程不挡具体对象链接，也不每天重复。Wiki的最近更新有效知识仍是默认阅读内容。

## 4. 所有页面的四层结构

1. **我在哪**：模块名；详情页显示对象名与返回入口。
2. **当前状态**：业务状态、正文保存状态、相关时间；两种状态不混为一谈。
3. **最可能做什么**：一个强调的主动作，至多两个并列常用动作。
4. **其他功能**：更多、历史、纠错、辅助面板；不与主动作同等突出。

列表默认用于找内容，详情默认用于看内容，点击“编辑”才展开维护表单。表单使用字段提示，提交前说明实际影响；关闭与返回必须保留草稿或明确询问丢弃，不能靠卸载视图消除输入。不要为了满足“少按钮”隐藏保存、返回或重要风险。

   ↓ 选择一个

| 层级 | 默认看到 | 高频动作 | 次级功能与保留边界 |
| --- | --- | --- | --- |
| 列表 | 公司/岗位/阶段/结果；是否有当前简历 | 选择机会、新建机会 | 刷新；公司管理在更多中，不抢占列表 |
| 新建 | 公司选择/输入、岗位；JD可后补 | 创建机会 | 在同一流程调用现有Company与Opportunity能力，不承诺新的跨owner原子提交；失败保留已建公司供继续选择，不重复建公司 |
| 概览 | 状态、已知日期、JD阅读摘要、当前资料入口 | 修改简历；记录实际进展 | 编辑岗位信息/补JD；变化历史；结束或纠错在更多中 |
| 简历 | 所属公司/岗位、当前纸面和保存状态 | 编辑、导出PDF | 命名版本、历史、复制来源；仍是同一Resume owner与现有对象链接 |
| 情报 | 本岗位情报；可明确切换查看公司情报 | 记录情报 | 来源/性质/确认状态可见；共享为公司情报另行明确确认，不能复制成双正本 |
| 沟通 | 未发送草稿、实际沟通和发送材料，明确分区 | 记录沟通、继续编辑草稿 | 首次投递记录与后续发送的原有区别保持 |
| 面试 | 真实轮次列表；练习单独区分 | 记录已发生或已确认的真实轮次 | 准备、文字稿、复盘；模拟不推进真实阶段 |
| Offer | 已收到条件与原件状态；暂无时先说明用途 | 记录实际收到的Offer | 分析是辅助；接受、撤回、条件历史保持原owner与真实依据 |

**首次投递不能丢：**概览在投递准备状态提供“记录已投递”；沟通内始终可找到“投递与发送材料”。首次投递和后续发送各守现有身份，不能只剩一个泛化的沟通记录。点按钮只是打开录入，不表示已发生；确认后由正式owner处理。

“下一步”基于现有业务状态推荐，不推断用户一定已投递、已面试或收到Offer。不知道日期可以保留未知；对方先联系，也能直接记沟通和真实面试，不要求补一条假投递。

同名公司不能自动合并。普通列表不显示UUID；选择出现同名歧义时，显示已有岗位关联等可读区别，并给每个独立候选临时可读标签；仍由用户选择。必要的稳定ID在技术详情可查，不假造公司介绍用于区分。

## 6. Wiki、Project、Employment

| 页面 | 用途提示 | 列表 / 阅读 | 主动作 / 次级入口 |
| --- | --- | --- | --- |
| Wiki | “这里放你以后还想找回和复用的职业资料。” | 最近更新的有效知识；默认可读范围不偷偷扩大到私有机会 | 记录一条知识；导入原始材料次级；来源、相关对象、修订按需查看 |
| 项目 | “记录你实际做过或正在做的项目。” | 名称、状态、个人项目/所属任职；详情突出目标、做过什么和相关材料 | 记录项目；编辑当前记录；参与关系、变更/纠错与历史按需进入 |
| 任职 | “记录一段真实工作经历，以及里面的人和项目。” | 公司、职位、当前/历史；详情突出这段工作的记录 | 记录真实任职；任职内人物/项目；结束、纠错、角色历史次级 |

个人项目无需先建任职。尚未真正开始工作，继续在机会/Offer记录，不提前创建现实任职。同名人物保持独立，由上下文和明确选择区分，不因姓名相同合并。

Wiki知识与原始材料分区：原始材料保留原话，Wiki写可复用的理解。导入流程仍为选择→预览→确认保存；取消不创建原件。情报正文仍在公司/机会，Wiki只引用，不制造另一份情报正文。

性质与来源提示靠近正文：Wiki保持“事实陈述 / 观察 / 待验证判断”；Research保持“事实陈述 / 推断 / 未知”，不为统一视觉强行统一枚举。用户采纳、事实陈述与独立核验的区别继续可见。

## 7. Resume

顶栏持续显示“公司 · 岗位 / 简历”和“返回所属机会”；编辑纸面优先。保存状态紧靠纸面，不让用户滚到别处才能确认是否保存。

常用工具：加粗、斜体、列表、对齐、撤销/重做。对齐用一组左/中/右选择；“姓名对齐”在身份区附近。常用工具在窄窗口可换成短工具组，但不能变成没有名称或无法操作的图标墙。

导出PDF与命名版本可直接找到；版本历史、从其他机会复制版本内容放入次级入口。复制明确是把所选版本内容复制到当前机会，不共享当前稿、不改变原归属。AI建议在本简历侧面打开，不跳到全局目标选择器。

姓名/联系方式旁必须说明：“这是你的基础资料，修改后会同步其他当前简历。”不能以局部编辑的外观掩盖全局Profile影响。正文格式、对齐、中文composition、选区和AI独立Undo保持原验收能力；改IA不能重建编辑器丢掉当前会话。

## 8. AI：从具体任务进入

普通入口用“帮我整理情报”“优化这份简历”“起草沟通内容”等任务名；不让首次用户先选 task/operation/UUID。只展示当前连接真正支持的能力；本地fake验证不能伪装成真实模型服务。当前真实DeepSeek已验范围为Research整理，不能据此承诺其他任务的真实Provider也可用。

用户流程：选择目标及材料 → 看完整读取/外发预览 → 明确授权 → 等待结果 → 查看建议 → 接受或拒绝。建议与正式正文分开；不自动Apply、不自动发消息、不自动推进机会状态。

发送确认页必须直接展示接收服务、真实模型、使用与外发材料、完整发送内容（含指令）、费用/预算与当前可用状态。原始字段/JSON副本可在技术详情，但不能把重要外发内容只放在技术详情里。新服务授权不能沿用已消费的J-07测试授权；未授权不联网。

结果未知直接告诉用户：“这次请求是否完成还不能确定。先检查结果，避免重复发送或重复扣费。”只在确有可查询回执能力时提供检查；不存在查询能力时诚实说明并等待用户判断。不自动重发，不把“继续保存”复用成“重新请求AI”。

## 9. Settings / Help

底部辅助入口：设置、帮助、反馈。打开辅助面板保留当前正文、选区和草稿；关闭回到原任务，不把整页维护表单插到业务Shell上方。

设置分组：我的基础资料；AI/Search连接；备份与恢复；导航偏好；高级资料维护。备份恢复、永久清除只在用户主动进入后出现。恢复点用时间、用途和可恢复状态命名；设备路径、copy kind/state、workspace ID二级展开。原rollback不因隐藏而删除。

“如何使用Career”包含问题导航、完整指南与“重新看新手教程”；每个页面也有“这个页面怎么用”。不增加第五个业务模块。工程验收控件（固定J-07查询、TEST DATA任务、受控飞书候选）不得出现在普通生产使用路径；开发诊断保留独立明确标识。现有App不具备正式live飞书读取UI，帮助不承诺已经有一键飞书导入。

## 10. 新手教程：4步，均可跳过

| 步骤 | 用户看到 | 动作 |
| --- | --- | --- |
| 1 | Career是你的长期职业工作台：求职、工作和积累都放这里 | 下一步 / 跳过 |
| 2 | 四个入口：Wiki存可复用资料；机会推进求职；项目记录做过的事；任职记录真实工作经历 | 下一步 / 上一步 / 跳过 |

## 11. 空状态、等待、错误和未知

| 状态 | 用户文案示例 | 下一步 |

| 无任职 | “真正开始一份工作后，在这里记录。” | 记录任职；还在求职则去机会 |
| 无情报/沟通/面试/Offer | 先说明该区用途，并强调只记录现实资料 | 一个对应记录按钮，不直接铺满空表单 |
| 筛选无结果 | “没有符合条件的内容，试试换个关键词或清除筛选。” | 清除筛选；不能误显示为未创建任何对象 |
| 读取中 | “正在打开这份资料…” | 骨架/局部等待；保留原输入，禁止重复提交 |
| 中文输入中 | “正在输入，完成后自动保存。” | 不保存未结束的composition |
| 保存失败 | “还没保存成功，你的输入保留着。” | 按真实失败原因给检查或再次保存，不只给错误码 |
| 保存结果未知 | “暂时无法确认是否保存。你的输入还在，请先检查保存结果。” | 检查是否保存；核对确认未记录后才能继续这次保存 |
| 冲突 | “另一处已更新这份资料。你的输入仍保留，请比较后决定。” | 比较两份；保留我的输入并保存 / 使用已保存内容；不自动覆盖 |
| 来源不可读 | “这份来源暂时无法打开，没有用其他内容替换。” | 保留引用、查看原因、重试读取；不偷换新版本 |
| 系统授权等待 | “正在等待macOS授权，请在系统窗口完成。” | 等待或取消，控制路径保持响应，不反复弹窗 |
| 授权取消/拒绝/超时/不可用 | 分别说明发生了什么，明确尚未发送 | 返回连接设置/重新授权；不自动联网 |

所有失败提示遵循：发生了什么 → 内容/外发现在处于什么状态 → 下一步做什么。复制技术详情便于反馈，但不得附带Key、token或无关私人正文。
