## 用户实际操作教程

1. 点击左上角的导航图标。看到 Wiki、机会、项目和任职后，说明侧栏已打开。
2. 点击「机会」。看到机会列表后，说明已进入机会页。
3. 点击「G5 Manual Test · Desktop Review」。看到机会详情后，说明选中了测试对象。
4. 点击「编辑本机会简历」。看到标题「G5 Manual Test · Desktop Review 的简历」后，说明进入正确简历。
5. 点击「简历优化提案」。看到简历区块复选框后，说明提案面板已打开。
6. 点击「项目」。看到「尚无项目」后，说明项目页已打开。
7. 点击「任职」。看到「尚无任职」后，说明任职页已打开。
8. 点击「机会」。看到测试机会详情后，说明回到了机会页。
9. 点击「反馈」。看到反馈内容区后，说明反馈页已打开。
10. 点击「返回原任务（保留反馈草稿）」。看到原机会详情后，说明已返回原任务。
11. 点击「编辑本机会简历」。看到已保存正文后，说明能重新打开 Resume。

以上教程只包含本轮实际走通的操作，不包含未成功的 PDF 导出或中文输入步骤。

## 最终回顾

- 用应用「视图」菜单完成放大、缩小和还原。

HUMAN_ONLY:
- 中文输入法候选操作：Computer Use 键入拼音和 Ctrl+Space 均未显示候选框，只插入了原始拼音。需要用户在 macOS 上手动切换到简体拼音输入源，再亲自输入「zhengniuwa」并从候选框选「蒸牛蛙」；不能据本轮判断中文输入是否工作。

FAIL:
- 提案接受后 Undo 出现保存冲突；解决后提案仍为 accepted，不能把原 Undo 路径记为通过。
- PDF 导出没有完成。按钮可点，但界面返回「请先完成当前资料保存或核对」；我试着保存未改动的基础资料，依次看到「基础资料保存结果待核对」「基础资料未登记，可明确继续原命令」和「基础资料保存结果待核对」。没有得到成功保存确认，也没有生成 PDF，因此停止额外业务处理。

部分通过:
- 键盘焦点在命名弹窗内循环，Shift+Tab 返回版本栏，关闭后正文焦点重新可用；但输入插入点位置没有恢复的可靠证据。
- Computer Use 的 `selectText` 操作没有准确选到完整目标；因此不能据此归因产品的鼠标选择行为。
- 窄窗口下实际输入、Undo 和版本历史按钮点击成功；实际宽度只估约 600px，且输入插入点不在点击预期位置。
- Wiki、机会、项目、任职、岗位情报、沟通、面试、Offer、反馈和资料维护入口均能找到并打开；反馈返回后临时 JD 草稿仍保留，随后已取消。Resume 回访后显示已保存。

UX CONFUSION:
- App 启动时直接显示简历正文，侧栏收起后左上角图标没有说明是导航入口。
- ⌘S 弹窗关闭后仍能输入，但插入文字出现在「经历」标题前；预先选中文字后按 Right 折叠光标的位置没有直接视觉确认。
- Resume 提案面板展开后会显示原始 JSON 与来源标识；「读取已有任务」项目名称是短 ID 和 revoked 状态，不容易理解下一步。
- PDF 导出受阻时只有「请先完成当前资料保存或核对」，没有指出具体哪个资料需要保存或如何核对。
- 视图菜单需要先按 Down 才能显示可选项，菜单路径对首次使用者不明显。
- 窄窗口时提案 JSON 和来源标识纵向占据很长页面，正文仍能看到，但需要连续滚动。

## 自动化可能掩盖的普通用户困难

本轮看到文字选择控制没有准确覆盖目标、关闭弹窗后的插入位置不易确认、Undo 进入保存冲突、窄窗口下提案 JSON 大量折行，以及 PDF 导出缺少具体处理指引。这些现象不能由“按钮可点击”或路由断言替代；选择误差是否来自产品鼠标交互尚未证实。
